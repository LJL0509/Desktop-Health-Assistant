# v0.7 开发与调试过程

版本：`v0.7.0`

日期：2026-08-12

## 1. 本轮目标

`v0.6.0` 已经能够生成每日健康报告，但需要用户手动执行命令。本轮将日报接入长期运行流程：

- 跨过午夜时自动生成前一天报告；
- 第二天首次启动时补生成缺失报告；
- 已有报告不重复覆盖；
- 摄像头和无摄像头模式都使用同一调度逻辑。

## 2. 自动生成规则

自动日报调度器维护当前本地日期，并执行两类检查：

- 启动检查：如果昨天的 JSON 或 Markdown 报告缺失，则补生成；
- 运行检查：检测到日期进入下一天时，先结算旧日期数据，再生成报告。

只有 JSON 和 Markdown 两个文件都存在时，才认为该日期报告完整。自动流程不会覆盖完整的已有报告。用户仍可运行：

```powershell
.\.venv\Scripts\python.exe scripts\daily_report.py --date 2026-08-11
```

主动重新生成指定日期。

## 3. 摄像头跨午夜

摄像头模式不能在午夜直接读取仍未结算的会话，否则当天最后一段姿势与眨眼数据不会进入报告。当前流程为：

1. 使用本地 `00:00:00` 作为准确日界线；
2. 在旧日志中结束当前姿势事件；
3. 写入旧会话姿势与眨眼汇总；
4. 关闭旧会话并生成前一天报告；
5. 创建新日期会话日志；
6. 保留已经完成的姿势和睁眼校准；
7. 重置每日姿势、眨眼、持续闭眼与提醒计数。

MediaPipe 的视频时间戳独立于日志会话，跨午夜继续严格递增，避免模型因时间戳重置报错。

## 4. 无摄像头跨午夜

无摄像头模式在生成报告前结束当天连续使用段，然后创建新一天活动跟踪器。新跟踪器以午夜为最早起点，即使用户在午夜前已经很久没有键鼠输入，也不会把新一天的使用段错误回推到昨天。

## 5. 失败与幂等

- 自动生成失败不会停止健康助手；
- 失败后等待 60 秒再重试，避免错误日志刷屏；
- 同一天正常轮询不会重复生成；
- 已有报告不会被自动覆盖；
- 强制结束造成的不完整会话继续由报告的数据质量说明标出。

## 6. 无数据报告

真实补生成测试发现，完全没有监控数据的报告曾显示“没有记录到问题”，容易被理解为健康正常。现已改为：

> 当天没有有效监测数据，无法评价电脑使用、姿势或眨眼情况。

缺失数据不再被解释为正常状态。

## 8. 已知限制与下一步

- 报告仍通过文件查看，没有应用内历史列表；
- 已存在报告需要用户手动命令刷新；
- 真实跨午夜自然运行仍需继续观察；
- 下一步适合增加系统托盘控制，让程序可以在隐藏摄像头窗口后继续运行，并方便暂停、恢复和打开最新报告。
