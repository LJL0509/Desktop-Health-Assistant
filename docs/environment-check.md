# 环境兼容性检查

检查日期：2026-08-09

## 检查结论

当前电脑支持项目所需的 MediaPipe Tasks API 和基础摄像头共享能力，可以继续进入最小技术原型阶段。

## 系统环境

| 项目 | 检查结果 |
| --- | --- |
| 操作系统 | Windows 11 家庭版中文版，Build 26200 |
| Python | 3.11.6，64 位 |
| 摄像头 | Integrated Camera，设备状态正常 |
| MediaPipe | 1.0.0，导入成功 |
| OpenCV | 5.0.0，导入成功 |

## MediaPipe 检查

- MediaPipe 原生图像桥接成功。
- `FaceLandmarker` API 存在。
- `PoseLandmarker` API 存在。
- MediaPipe 1.0.0 不再提供旧版 `mp.solutions` API，项目必须使用新的 Tasks API。
- 本次只验证运行库和接口，正式原型仍需下载官方模型并执行一次人脸与姿态推理测试。

## 摄像头检查

| 测试 | 结果 |
| --- | --- |
| Media Foundation 单路打开并读取 | 通过，640 x 480 |
| DirectShow 单路打开并读取 | 通过，640 x 480 |
| 两路 Media Foundation 同时读取 | 通过 |
| 第二路打开后第一路继续读取 | 通过 |
| 释放后重新打开 Media Foundation | 通过 |

两路 Media Foundation 测试通过，说明当前 Windows 和摄像头驱动具备基础共享能力。该结果不能保证 QQ、微信或腾讯会议一定采用兼容的共享方式。

## 后续联调

最小原型完成后，需要进行一次人工联调：

1. 先启动健康助手摄像头预览。
2. 再打开 QQ 视频设置页，检查 QQ 能否同时获得画面。
3. 交换启动顺序再次测试。
4. 如果 QQ 无法共享，验证助手暂停后是否立即释放摄像头。
5. 记录摄像头恢复和重新校准行为。

检查过程中只在内存中读取视频帧，没有保存图片或视频。
