# v0.4 开发与调试过程

版本：`v0.4.0`

日期：2026-08-12

## 1. 本轮目标

补充每日健康报告缺少的连续电脑使用数据，同时避免增加重复通知：

- 估算每段连续使用电脑的时长；
- 在日报中统计段数、总时长和最长一段；
- 不记录具体按键、鼠标位置或应用内容；
- 不把电脑交互时间直接描述为真实久坐；
- 由补水提醒统一承担喝水和离屏休息提示。

## 2. 数据来源与隐私

程序调用 Windows `GetLastInputInfo`，只获得“距离上一次键盘或鼠标输入经过了多少秒”。程序不会读取：

- 按下了哪个键；
- 输入的文字；
- 鼠标点击位置；
- 当前打开的窗口或应用内容。

本地活动日志只保存连续使用的开始、结束、持续时长和结束原因。

## 3. 连续使用状态

当最近存在键鼠输入时，程序开始或延续当前使用段。连续 5 分钟没有输入后，当前使用段在最后一次输入时间结束；下一次输入开始新的一段。

5 分钟是产品默认值，不是国家标准或医学危险阈值。它用于过滤短暂思考、阅读等停顿，同时把较长离开视为一次休息。

## 4. 提醒合并

初始实现曾计划在连续使用 60 分钟后单独发送休息通知。实际讨论后认为该通知与每 60 分钟一次的补水提醒目标重叠，会造成不必要的打扰，因此最终设计为：

- 删除独立的固定 60 分钟休息通知；
- 保留连续使用统计供日报使用；
- 补水通知改名为“补水与休息提示”；
- 文案改为“已经一段时间没有记录喝水了。喝点水，也离开电脑活动几分钟。”；
- “已喝水”按钮仍只记录饮水并重置补水计时。

## 5. 日报接入

日报新增“连续电脑使用”部分：

- 记录到的使用段数；
- 累计使用时长；
- 最长连续使用时长；
- 尚未结束的使用段统计到报告生成时刻。

报告同时明确指出：键鼠无输入可能发生在看视频或阅读期间，因此不代表用户真正离开；电脑活动也不等于用户始终坐着。

## 6. 实际验证

- Windows 空闲时间接口在当前设备成功返回空闲秒数；
- 状态机完成开始、短暂停顿、5 分钟重置和退出结算测试；
- 日报完成已结束和未结束活动段测试；
- 合并后的补水与休息通知成功弹出；
- 用户点击“已喝水”后记录到测试按钮回调；
- 测试动作使用 `test_` 事件，不计入真实饮水量和日报；
- 全部 68 项自动测试通过；
- Python 编译和依赖检查通过。

## 7. 当前限制与下一步

- 看视频、阅读或使用手柄时可能因为没有键鼠输入而低估连续使用；
- 不能从 Windows 输入状态判断用户是否坐着；
- 摄像头程序和独立提醒服务不能同时运行，否则可能重复统计；
- 下一阶段应整合统一桌面运行入口，再开始眨眼频率监测。
