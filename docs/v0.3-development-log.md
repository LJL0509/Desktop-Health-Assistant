# v0.3 开发与调试过程

版本：`v0.3.0`

日期：2026-08-12

## 1. 本轮目标

在 `v0.2.0` 姿势监控基础上加入两个不依赖摄像头的生活提醒，并把已有本地事件整理成可阅读的每日健康提示报告：

- 长时间未记录喝水时提醒；
- 每天凌晨 1 点进行睡眠提示；
- 汇总当天姿势问题、提醒记录和数据覆盖情况；
- 不把缺失数据解释为健康，也不把行为记录写成医学结论。

## 2. 补水提醒的边界

程序不能在没有额外传感器的情况下知道用户是否真的喝了水，因此本版不使用摄像头识别喝水动作。实际逻辑是：

- 默认从程序启动、上一次补水提醒或上一次“已喝水”记录开始计时；
- 60 分钟没有新记录时弹出补水提醒；
- 用户点击“已喝水”后默认记录 250 ml，并重新开始计时；
- 未确认时每过一个完整间隔最多再次提醒一次；
- 报告使用“未记录”或“未确认”，不声称用户一定没有喝水。

60 分钟和 250 ml 均为可调整的产品默认值，不是医学危险阈值或适用于所有人的饮水建议。

## 3. 睡眠提示

提醒服务按本机时区每天凌晨 1 点触发一次，文案固定为：

> 哪个有意思，你是觉得现在睡觉然后明天再干事情有意思还是现在熬夜明天躺着有意思？

程序在凌晨 1 点以后才启动时不会补发已经错过的提醒。同一天内重复轮询也不会重复发送。

## 4. Windows 弹窗调试

第一次实际测试中，通知进入了 Windows 通知中心，但没有显示横幅。随后完成以下修改：

- 通知器改为 `InteractableWindowsToaster`；
- 使用 `ToastScenario.Reminder`；
- 显示时长改为 `ToastDuration.Long`；
- 多个测试通知之间增加 4 秒间隔。

修改后用户确认通知横幅正常弹出，“已喝水”按钮也正确写入 250 ml 测试动作。

## 5. 每日健康报告

日报生成器同时读取：

- `data/monitor-sessions/` 中的姿势与摄像头会话事件；
- `data/reminders/` 中的补水、睡眠提醒和用户确认事件。

每日报告生成两种文件：

- JSON：保留结构化统计，供后续界面和趋势分析使用；
- Markdown：供用户直接阅读。

当前报告包含：

- 监控会话数、运行时长、暂停时长、有效监测时长和数据覆盖率；
- 头部前伸、头部过低的累计时长、次数、最长一次和提醒次数；
- 喝水记录次数、估计总量、补水提醒和最长未确认时长；
- 睡眠提醒和确认次数；
- 不完整会话、估算时长、未结束姿势事件等数据质量说明；
- 根据当天最突出问题生成的非诊断性改进方向。

测试通知以 `test_` 开头并在日报中排除。监控日志中的 `water_recorded_from_keyboard` 只是提醒日志的镜像，也不参与补水总量统计，避免重复计数。

## 6. 真实日志验证

使用 2026-08-12 的实际日志生成报告，结果正确显示：

- 1 个被强制结束的不完整监控会话；
- 2 分 40 秒估算运行时长；
- 81 秒已知摄像头数据缺失；
- 3 次测试过程中的手动喝水记录，共 750 ml；
- 0 次真实补水提醒和 0 次真实睡眠提醒；
- 1 段未正常结束、因此未计入累计时长的姿势事件。

这次结果证明报告能够暴露数据不足，而不是把不完整日志错误解释为正常状态。

## 7. 验证结果

- 补水和睡眠 Windows 横幅均完成实际测试；
- 补水按钮动作记录通过；
- 提醒调度、状态持久化和日报聚合自动测试通过；
- 全部 61 项自动测试通过；
- Python 编译检查通过；
- `pip check` 未发现损坏依赖；
- 日志和报告均不包含照片或视频。

## 8. 已知限制与下一步

- 补水记录依赖用户确认，不能自动判断是否实际喝水；
- 最长未确认喝水时长按连续提醒次数估算；
- 日报目前需要手动运行生成；
- 全天电脑使用、连续久坐、固定姿势、眨眼和屏幕距离仍显示为“尚未监测”；
- 下一阶段优先实现独立于摄像头的电脑活动与连续使用监测，为久坐提醒和日报提供可靠数据。
