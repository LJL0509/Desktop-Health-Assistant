# v0.1 开发与调试过程

版本：`v0.1.0`

日期：2026-08-09 至 2026-08-10

## 1. 从需求开始

项目没有直接从写代码开始，而是先明确实际使用场景：用户每天使用电脑约 6 小时，单次连续使用可达到 2 小时，希望监控眨眼、屏幕距离、姿势、饮水和久坐，并只在异常持续一段时间后提醒。

首个技术模块选择脖子前倾监控。隐私原则同时确定：本地处理摄像头，不保存、不上传照片或视频，只保存事件和汇总数值。

## 2. 环境和摄像头验证

项目在 Windows 11、Python 3.11.6 上建立独立虚拟环境，安装 MediaPipe 1.0.0。验证结果：

- Face Landmarker 与 Pose Landmarker API 可用；
- Media Foundation 与 DirectShow 均能读取内置摄像头；
- 两路 Media Foundation 可以同时读取；
- 摄像头释放后能够重新打开。

MediaPipe 1.0 已移除旧版 `mp.solutions` API，因此项目统一采用 Tasks API。

## 3. 第一个错误：模型预测不等于真实可见

初版关键点预览只检查 MediaPipe 的 `visibility`，导致肩膀已经离开画面时仍显示 `FOUND`。模型实际上是在根据头部和躯干推测画外肩膀。

程序随后增加：

- 坐标是否在画面内；
- 关键点存在度和可见度；
- 肩膀是否位于下巴下方；
- 肩宽与脸宽比例是否合理。

该问题让项目明确了一条原则：AI 输出必须经过画面几何和人体结构验证。

## 4. 第二个问题：判断过于苛刻

严格规则解决了画外误判，却把位于画面最下方的真实肩膀判为缺失。通过用户截图重新推理，发现双肩 `y` 坐标约为 0.99，只是触发了人为设置的 2% 安全边距。

边界被放宽到完整画面范围，并增加 `FOUND / PARTIAL / MISSING` 三级状态。另一张截图中肩关节中心位于画面下方约 2% 至 5%，但模型置信度接近 0.99，因此定义为 `PARTIAL`，不再与完全缺失混为一谈。

## 5. 重新审视目标

用户最舒服的姿势只能看到脸和脖子，无法持续看到肩关节。项目没有要求用户为了算法改变舒适坐姿，而是重新确认目标：肩膀不是最终识别对象，其最大作用是判断头部是否相对身体前移。

算法因此改为“虚拟头肩锚点”：允许肩关节中心位于画面下方，只要人体比例合理，并通过时间稳定性验证。虚拟锚点只服务于头部前移判断，不用于圆肩和肩膀倾斜。

## 6. 三组动作实验

第一次实验采集：

1. 正常坐姿；
2. 只向前伸头；
3. 整个上身靠近屏幕。

肩膀直接可见时，三维头肩深度、颈部比例和脸肩相对缩放能够区分三种动作。切换到舒适位置的虚拟锚点后，三维深度不再可靠，但 5 秒窗口中的相对缩放仍能区分：

- 只伸头：脸宽增长约 16%，虚拟肩宽增长约 8%；
- 整体靠近：脸宽增长约 19%，虚拟肩宽增长约 17%。

因此虚拟锚点模式改为比较脸宽增长和虚拟肩宽增长，不再把三维头肩深度作为主判定。

## 7. 从多状态改为两个独立系统

初版持续监控同时输出正常、头前伸、整体靠近和复杂姿势，状态容易闪烁，也混淆了两个问题。

用户明确提出：

- 正常坐姿与整体靠近在脖子系统中都属于正常；
- 脖子前倾需要明确标出；
- 屏幕距离应该由另一个系统单独判断。

分类器随后简化为 `NECK NORMAL` 与 `NECK FORWARD`，并增加 3 秒状态确认。根据人工反馈，脸宽增长和脸/虚拟肩宽比例增长的候选下限调整为 8%。

## 8. 数据不足提醒

用户发现长时间 `DATA INSUFFICIENT` 往往意味着脸太近、弯腰过低或离开有效画面。项目增加独立提醒：

- 数据连续不足 10 秒才提示；
- 根据原因显示“移动远一点”“坐直”或“检查摄像头位置”；
- 数据恢复后自动清除；
- 数据不足不记为脖子前倾；
- 主动暂停摄像头时不计时。

## 9. v0.1 验证结果

最终受控验证记录 25 次人工反馈：

- 正确 23 次；
- 错误 2 次；
- 人工反馈准确率 92%；
- 数据不足提醒触发 3 次，恢复 3 次。

两次错误均为较轻前倾漏检。项目没有继续降低阈值，因为日志中也存在短暂超过阈值但用户确认正常的样本，继续针对少量动作调参可能导致过拟合。

## 10. v0.1 决策总结

- 优先适应用户自然坐姿，不要求用户适应摄像头；
- AI 预测关键点必须通过有效性和稳定性检查；
- 直接肩膀与虚拟锚点采用不同算法；
- 脖子姿势与屏幕距离保持独立；
- 使用个人基线、5 秒平滑和 3 秒状态确认；
- 数据不足是独立状态，不等同于健康异常；
- 当前阈值是个人实验参数，不是医学标准；
- v0.1 到此冻结，后续功能在新版本继续。
