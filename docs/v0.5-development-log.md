# v0.5 开发与调试过程

版本：`v0.5.0`

日期：2026-08-12

## 1. 改版原因

`v0.4.0` 有两个可以长期运行的脚本：

- 摄像头主程序，同时运行姿势、补水、睡眠和连续使用模块；
- 无摄像头提醒服务，运行补水、睡眠和连续使用模块。

如果用户误把两个脚本同时打开，补水提醒和连续使用记录会重复。本轮目标是提供一个日常入口，并从系统层面阻止第二个实例运行。

## 2. 统一入口

新的日常启动命令为：

```powershell
.\.venv\Scripts\python.exe scripts\desktop_health_assistant.py
```

默认启动完整摄像头监控。无需摄像头时使用：

```powershell
.\.venv\Scripts\python.exe scripts\desktop_health_assistant.py --no-camera
```

无摄像头模式仍保留补水与休息提示、凌晨睡眠提示和连续电脑使用统计。

## 3. 单实例保护

程序使用 Windows 命名互斥量 `Local\\DesktopHealthAssistant.SingleInstance`。统一入口、摄像头旧入口和提醒旧入口使用同一个互斥量，因此：

- 任意一个入口已经运行时，其他入口无法再次启动；
- 第二个进程显示“Desktop Health Assistant 已经在运行，请勿重复启动。”；
- 第二个进程使用退出码 `2` 结束；
- 第一个进程保持运行，不会受到影响。

互斥量只存在于内存中，进程退出后由 Windows 释放，不创建额外锁文件。

## 4. 实际验证

使用统一入口启动完整模式后完成以下检查：

- 摄像头窗口正常出现；
- 第一个进程持有单实例锁；
- 同时启动 `--no-camera` 时，第二个进程被拒绝并返回退出码 `2`；
- 第一个摄像头进程继续运行；
- 用户按 `Q` 后，姿势会话写入汇总和结束事件；
- 连续使用会话写入 `service_stopped` 结束事件；
- Windows 通知线程清理完成后进程正常退出。

## 5. 验证结果

- 2 项 Windows 命名互斥量测试通过；
- 2 项统一入口参数测试通过；
- 全部 72 项自动测试通过；
- Python 编译和依赖完整性检查通过；
- 没有新增摄像头照片、视频或输入内容记录。

## 6. 下一步

统一运行入口完成后，下一项核心监测功能是眨眼频率。仍需遵守以下边界：

- 只有脸部和眼睛清晰可见时才统计；
- 面部缺失不能记为没有眨眼；
- 先完成个人睁眼基线和受控眨眼测试，再决定提醒窗口；
- 屏幕距离、固定姿势时长和自动日报仍在后续范围内。
